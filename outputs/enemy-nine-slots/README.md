# 큐브 축소 및 타일당 9마리 제한

후속 변경: [출발 자리 유지 및 오른쪽 빈자리 탐색](../enemy-preferred-slot/README.md)을 적용했습니다. 현재 이동은 자기의 상대 자리를 먼저 유지하고, 막혀 있을 때만 오른쪽으로 탐색합니다.

후속 변경: [면 에셋·시작 면 랜덤화](../enemy-random-faces/README.md)를 적용하여 재소환 때 시작 면을 다시 뽑되 처음 보이는 그림은 정방향으로 놓습니다. 크기와 9자리 제한은 유지됩니다.

- `Enemy.prefab` 루트 크기를 기존의 1/3로 줄였습니다. 화면상 면적은 약 1/9이고, 큐브 한 변은 약 0.4444 월드 단위입니다. 2D 충돌체·HP바·굴림 높이도 루트와 함께 축소됩니다.
- Stage1의 1.5 크기 패스 타일에 중심 간격 0.5인 고정 3×3 자리를 배정합니다. 중앙부터 빈자리를 사용하며, 다른 적이 떠나도 기존 적의 자리는 바뀌지 않습니다.
- 점유와 도착 예약을 합쳐 물리적인 한 타일에 최대 9마리만 허용합니다. 같은 셀을 여러 번 방문하는 경로도 정원을 공유합니다.
- 목적지가 가득 차면 현재 칸에서 이번 이동을 끝냅니다. 다음 이동 기회에 다시 시도합니다. 막힌 첫 이동은 첫 이동 완료로 처리하지 않습니다.
- Start도 정원에 포함합니다. 가득 차면 추가 소환을 하지 않으며 웨이브 소환 완료 수를 증가시키지 않습니다. 미소환 적은 기존 소환 턴 일정 안에서 재시도합니다.
- 사망·풀 반환·이동 중단 시 점유와 예약을 함께 해제합니다. 풀 재사용 시 정면과 체력을 초기화하고 빈자리에 배치합니다.

검증 결과: 전체 게임 C# 컴파일 성공. Unity 6000.3.9f1 별도 프로젝트의 PlayMode에서 실제 프리팹으로 9개 배치와 타일 내 경계·축소 충돌체, 10번째 풀 소환 차단, 예약 중복 방지, 10번째 등록 실패 시 출발 점유 보존, 막힌 전진/역진과 빈자리 재시도, 9마리 동시 굴림과 서로 다른 착지점, 풀 반환·이동 중단 후 예약 해제, 같은 물리 셀의 여러 경로 방문 공유, Start 정원에 따른 소환 수 보존을 통과했습니다. 설치된 프리팹·재질·풀·Stage1 참조 검사도 통과했습니다.

`nine-cubes-on-tile.png`는 위 PlayMode 검사에서 실제 Unity 카메라로 렌더링한 결과입니다. `ValidateNineSlots.cs`는 별도 검증 프로젝트용이며 실제 게임 Assets에는 설치하지 않습니다. 전체 Stage1 장시간 플레이는 별도로 수행하지 않았습니다.
