# 전체 타워·몬스터 캐릭터 에셋 검토

검토 범위는 실제 카탈로그의 일반 타워 **56종**, 시너지 타워 **14종**, 몬스터 **27종**, 총 **97종**이다. 초상 원본, 눈 부분 확대, 장비 마스크, 보정본, Unity 렌더링을 순서대로 검토했다. 투사체·타격 이펙트 애니메이션은 이번 캐릭터 초상 검토의 대상이 아니다.

## 발견 및 수정

| 항목 | 발견 내용 | 처리 |
|---|---|---|
| 일반 타워 눈높이 | 초상별 기준점이 논리 141~171px 사이에 분산 | 160px 기준으로 정렬 |
| 일반 타워 얼굴 크기 | 일부 비인간형의 눈 간격이 최대 약 64px로 큼 | 논리 눈 간격 39.5px 기준으로 보정 |
| 일반 타워 하단 | 237~248px로 서로 다름 | 244px 기준선으로 통일 |
| 시너지 타워 | 눈높이·얼굴 배율·하단에 차이 | 같은 논리 좌표 기준으로 보정 |
| 불도마뱀 | 단순 축소 보정본에서 목과 몸이 길고 좁게 보임 | 기존 디자인을 참고해 짧은 목·넓은 어깨의 상반신으로 새로 제작 후 규격 적용 |
| 몬스터 27종 | 기존 공통 크기와 마스크 기준 충족 | 파일 변경 없이 전수 확인 |
| Unity 임포트 | 해상도·분할·피벗·PPU·필터·압축·색 공간 정상 | 기존 설정 유지 |
| 카탈로그 참조 | 일반 56개 + 시너지 14개 참조 정상 | GUID·스프라이트 fileID 유지 |

수정한 실제 게임 파일은 `Assets/4. Asset/2. Tower/TowerCharacter/`의 **15개 PNG 아틀라스**다. 그 안의 70개 초상에 공통 레이아웃을 적용했다. `.meta`, 카탈로그, 프리팹, 게임 코드는 이 작업에서 수정하지 않았다. 기존 필터 등 사용자 설정도 유지했다. 몬스터의 초상·마스크·외형 에셋 27세트는 검토 전 백업과 바이트 단위로 동일하다.

## 공통 규격과 예외

논리 256×256 좌표에서 눈 중앙 `(128,160)`, 눈 간격 `39.5`, 몸 하단 `244`를 기준으로 한다. 눈과 얼굴의 상부는 균일 배율을 유지하고, 턱·수염 아래의 상반신을 하단 기준선에 맞춘다. 머리장식과 종별 실루엣은 유지한다. 좌표는 `layout-config.json`의 시각 검토한 동공 기준점이며, 모든 종의 털·왕관 외곽 크기가 같다는 뜻은 아니다.

- 일반·시너지: 아틀라스 내부 256×256 셀, 192 PPU, 중앙 피벗.
- 몬스터: 512×512 텍스처, 같은 256 논리 좌표의 두 배. 실제 큐브의 크기와 한 타일의 3×3 점유 규칙은 게임 코드에서 관리한다.
- 오딘: 안대를 유지하고 가려진 눈의 위치를 추정해 정렬했다.
- 브록·에이트리: 두 얼굴 각각의 눈 간격 평균을 사용한다. 두 사람을 가로지르는 거리를 한 사람의 눈 간격으로 취급하지 않았다.
- 불도마뱀: 내장 `image_gen`으로 재제작했다. 불꽃 관과 넓은 상반신에 별도 배율 보정을 적용해 얼굴 크기와 전체 상반신 비율을 맞췄다. 생성 프롬프트는 `salamander-prompt.txt`, 원본은 `Salamander-generated.png`다.

## 검증 결과

- 97종의 유효한 알파, 가장자리 잘림, 하단 기준선 확인. 불투명 영역의 캔버스 가장자리 접촉 0.
- 타워 70개 카탈로그 참조, 15개 아틀라스의 기존 스프라이트 ID와 임포터 바이트 보존 확인.
- 몬스터 마스크 27개: 이진 RGB, 초상 밖 침범 0, 눈·얼굴 검사 영역의 침범 0. 자홍색 오버레이로 전체 마스크를 시각 검토했다.
- Unity **6000.3.9f1**에서 보정 전 70개 스프라이트의 분할·피벗·PPU·실제 bounds 확인. 모든 스프라이트가 전체 256 셀의 경계를 사용하므로 표시 코드 수정은 필요하지 않았다.
- 보정 후 Unity에서 일반 14문양 × 4직군 × 5티어 = **280조합**, 시너지 **14종**, 총 **294장** GPU 렌더링 완료. 카탈로그 누락·규격 불일치·빈 렌더·오류 셰이더 검사 통과.
- 몬스터는 바뀐 파일이 없으므로 앞서 수행한 실제 플레이/상태색 162장 검증과 동일 입력임을 확인했다.

Unity 검증은 원본 프로젝트와 분리된 프로젝트에서 실제 에셋·카탈로그·팔레트를 복사하여 진행했다. 타워는 실제 `TowerVisual`의 레이어 위치/캔버스 규칙을 사용하는 SpriteRenderer 렌더 검증이며, 원본 URP 스테이지 전체 전투나 스테이지별 몬스터 소환 연결 테스트는 아니다. 몬스터의 플레이 검증 범위는 `../remaining-monsters-v1/unity-runtime-verification.json`에 명시되어 있다.
