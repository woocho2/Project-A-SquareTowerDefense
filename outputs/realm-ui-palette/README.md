# 보드와 UI 월드 색상

타일의 실제 PNG 바탕색과 장식색을 기준으로 열 월드의 보드·UI 색상을 맞췄습니다. 기존 장식, 위치, 투명도를 보존하는 스크립트 방식입니다. 바탕은 무늬 없이 약한 명암만 사용합니다.

## 저장 위치와 사용

- 보드: `Assets/4. Asset/1. BackGround/Tile_BoardFrame_All_Atlas.png`. 기존 스프라이트 GUID, 잘라낸 위치와 RuleTile 참조를 유지합니다.
- UI: `Assets/4. Asset/5. UI/Themes/<Realm>/Simple/`, `Sliced/`.
- A는 타워 스폰과 같은 밝은 바탕, B는 테두리의 강조색, C는 패스와 같은 짙은 바탕, Frame은 속이 투명한 빈 프레임입니다. 배경과 Frame을 겹쳐 사용합니다.
- Simple에는 아래 비율을 각각 단일 스프라이트 PNG로 저장합니다. 스프라이트 border는 0입니다.
- Sliced에는 128×128 정사각형을 따로 저장합니다. border는 기존 프레임과 같은 48px이고 중앙만 늘려 사용하는 용도입니다. 여기서 사용자의 `1:1(슬라이더)`를 Unity의 Sliced로 해석했습니다.

| 비율(가로:세로) | 크기 |
|---|---|
| 1:1 | 128×128 |
| 1:2 | 128×256 |
| 1:3 | 128×384 |
| 1:4 | 128×512 |
| 2:3 | 256×384 |
| 2:1 | 256×128 |
| 3:1 | 384×128 |
| 4:1 | 512×128 |
| 3:2 | 384×256 |

월드마다 10개 형태 × 4개 레이어 = 40개 PNG, 전체 400개입니다. Pixels Per Unit은 128이고, 투명 배경·Clamp·Bilinear·압축 없음·Mip Map 없음으로 설정합니다.

## 게임 연결

Canvas 프리팹의 기존 테마 이미지 141개를 새 에셋에 연결했습니다. UI 위치·크기·앵커·버튼·슬라이더 동작과 텍스트는 유지합니다. 기존 768×128/128×768 이미지는 요청한 최장 비율인 4:1/1:4를 사용합니다. 기존 정사각형 Sliced는 별도 1:1 Sliced를 사용하고 직사각형은 비율별 Simple을 사용합니다. Filled 이미지는 채움 동작을 유지합니다.

Canvas에 UIStageThemeController를 연결하고 열 월드의 새 스프라이트 참조를 직렬화했습니다. 테마를 교체해도 A/B/C/Frame 역할과 비율이 유지되고, 이미지의 border에 맞춰 Simple/Sliced를 선택합니다. Inspector에서 현재 스테이지 테마를 선택할 수 있습니다. 기존 44개 UI 아틀라스도 동일한 색상으로 수정해 메뉴 등 남아 있는 참조를 보존했습니다.

`preview.png`는 전체 월드의 보드와 합성 UI 비교입니다. `preview.html`에서는 월드·바탕 종류를 바꿔 비율별 실제 PNG를 확인할 수 있습니다. `palette.json`은 색상, `assets.json`은 400개 파일의 경로·크기·GUID·레이어 목록입니다. `source/`에는 변경 전 원본을 보관합니다. 재생성은 `Build-RealmUI.ps1`을 실행합니다.
