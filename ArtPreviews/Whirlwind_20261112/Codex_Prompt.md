# 휠윈드(도끼 광역 스킬) 손그림 연출 플립북 3종 — Codex 제작 지시서

작업 전에 `Assets/25. AI 에셋파일 생성규칙.txt`를 끝까지 읽고 따른다. 특히 7장 "연출 그림 (Resources/Effects/FX_*)" 규격이 적용된다.
게임 코드는 수정하지 않는다. 코드 연결은 이미 끝나 있다 (`AxeSplashSkillEffect.cs`, `Assets/Resources/FlipbookFx.shader`).

## 0. 목표와 연출 흐름

모바일·PC 상용 액션 RPG의 회전베기 스킬 수준의 손그림 2D 연출. 일본 애니메이션 작화 이펙트(작화 FX) 스타일:
날카로운 형태의 큰 면, 끝이 뾰족하게 빠지는 획, 속도감 있는 곡선, 명확한 밝은 날선과 어두운 몸통의 대비.
흐릿한 에어브러시·연기 덩어리·사진 질감·3D 렌더·픽셀아트로 만들지 않는다.

게임 안에서의 흐름(약 1초):
1. 원화 대도끼(`FX_WhirlwindGreatAxe.png`, 기존 그림 유지)가 뒤로 젖혀졌다가 타워 중심을 축으로 한 바퀴 돈다.
2. **회전 궤적**(`FX_WhirlwindSlash_Atlas`)이 도끼날 끝을 따라 붙어 돌며 커진다.
3. 날이 지나가는 적마다 **타격**(`FX_WhirlwindHit_Atlas`)이 터진다.
4. 회전이 멈추면 궤적은 바람 갈래로 흩어지고, 발밑에 **충격파**(`FX_WhirlwindBurst_Atlas`)가 퍼진다.

## 1. 공통 규격 (3장 모두)

- 투명 배경 PNG(RGBA). 그림은 **흰색~회색만** 사용한다. 색은 게임 셰이더가 칠한다.
  - 명암이 곧 색: 흰색(255) = 가장 뜨거운 날선(흰빛), 밝은 회색 = 주황빛 중간, 어두운 회색(~90) = 짙은 핏빛 바깥.
  - 따라서 "밝은 날선 → 중간 몸통 → 어두운 가장자리"가 명암으로 분명하게 나뉘어야 한다.
  - 검정·유색 픽셀 금지. 배경을 검정으로 칠하지 않는다.
- 4 × 4 칸, 총 16프레임. 재생 순서: **왼쪽 위에서 오른쪽으로, 위 줄에서 아래 줄로**(행 우선). 0번 = 왼쪽 위, 15번 = 오른쪽 아래.
- 칸마다 사방 최소 16px 투명 여백. 그림이 칸 경계에 닿거나 옆 칸으로 넘어가면 불합격.
- 모든 프레임은 **같은 중심점·같은 배율**에서 그린다(칸마다 위치가 흔들리면 재생 시 떨림).
- 알파: 경계는 안티앨리어싱으로 자연스럽게, 그 외 투명 영역은 정확히 알파 0.
  **옅은 잡티·점묘·디더 노이즈·반투명 안개를 칸 전체에 깔지 않는다.** (기존 화염 아틀라스가 이 문제로 지저분함)
- 연속 프레임은 형태가 이어져야 한다(프레임 사이에 갑자기 다른 그림으로 바뀌지 않게). 게임이 이웃 프레임을 섞어 부드럽게 재생한다.
- 글자·테두리·바닥 그림자·배경 금지.
- 저장 위치: `Assets/Resources/Effects/` (아래 파일 이름 그대로. 이름이 다르면 게임이 못 찾는다)
- 임포트 설정(7장): Texture Type Default, Alpha Is Transparency 켬, Wrap Clamp, 압축 없음(Compression None), Mip Map 끔, Max Size는 파일 크기 이상.

## 2. FX_WhirlwindSlash_Atlas.png — 회전 궤적 (가장 중요)

- 크기 **2048 × 2048**, 칸 512 × 512.
- **위에서 내려다본 원형(정원)으로 그린다.** 납작한 타원으로 그리지 않는다 — 게임이 회전면 기울기에 맞춰 세로로 눌러 준다.
- 칸 중심 = 회전축(타워 중심). 궤적의 **가장 밝은 바깥 날선**은 중심에서 **반지름 205px** 원 위를 지난다(칸 반폭의 80%).
  몸통은 그 원의 **안쪽으로** 펼쳐지고, 바깥쪽으로는 가는 바람 갈래만 최대 30px까지 허용(16px 여백 유지).
- 방향 규칙(필수):
  - **궤적의 머리(가장 굵고 밝은 앞끝)는 항상 칸 중심 기준 3시 방향(오른쪽)에 있다.**
  - 꼬리는 머리에서 **시계 방향**(3시 → 6시 → 9시 → 12시 쪽)으로 뻗으며 점점 가늘고 어두워져 뾰족하게 끝난다.
  - 게임이 이 판을 도끼날 각도에 맞춰 통째로 돌린다. 그래서 프레임마다 회전시키지 말고, 머리 위치는 3시로 고정한 채 꼬리 길이와 형태만 변하게 그린다.
- 프레임 구성:
  - 0~2: 머리 근처의 짧은 초승달 획(꼬리 30°→90°). 가늘고 날카로움.
  - 3~6: 꼬리가 150°→270°로 길어지며 굵어짐. 머리에 흰 날선, 몸통 중간 회색, 바깥 가장자리 어두운 회색 띠.
    몸통 안쪽에 속도선(호를 따라가는 가는 결 2~3줄)을 넣어 회전감을 준다.
  - 7~11: 최대 길이(약 300°)·최대 두께 유지(약 70~90px). 프레임마다 결과 가장자리 모양만 조금씩 달라져 살아 움직이는 느낌. 거의 한 바퀴 닫힌 고리처럼 보인다.
  - 12~15: 흩어짐. 고리가 여러 갈래의 뾰족한 바람 조각으로 갈라지며 바깥으로 살짝 퍼지고, 밝기가 회색으로 내려가 15번에서 거의 사라짐(작은 조각 몇 개만).
- 금지: 고리 전체를 균일한 두께의 도넛으로 그리기, 흐린 원형 그라데이션, 도끼 그림 넣기.

## 3. FX_WhirlwindHit_Atlas.png — 적 타격

- 크기 **1024 × 1024**, 칸 256 × 256. 칸 중심 = 맞은 적의 중심.
- 기본 방향: **베인 자국이 가로(좌↔우)로 그어진다.** 게임이 칼날 진행 방향으로 돌려 준다.
- 프레임 구성:
  - 0~1: 칸 중심에 짧고 강한 흰 섬광(뾰족한 4~6갈래 별 모양, 둥근 빛 덩어리 금지).
  - 2~5: 가로로 길게 그어지는 날카로운 초승달 베기 자국(양 끝이 바늘처럼 뾰족, 가운데가 가장 굵고 흰색). 칸 폭의 약 85%까지.
    베기 자국과 함께 뾰족한 파편 조각 4~6개가 진행 방향(오른쪽 위·오른쪽 아래)으로 튄다.
  - 6~10: 베기 자국이 가운데부터 갈라져 얇아지고, 파편이 더 멀리 날아가며 작아짐. 밝기 흰→회색.
  - 11~15: 남은 획 조각이 사라짐. 15번은 거의 빈 칸.
- 짧고 강하게 읽혀야 한다(게임에서 0.3초에 16프레임 재생).

## 4. FX_WhirlwindBurst_Atlas.png — 마무리 충격파

- 크기 **2048 × 2048**, 칸 512 × 512.
- **위에서 내려다본 정원**으로 그린다(게임이 바닥 기울기에 맞춰 눌러 준다). 칸 중심 = 타워 중심.
- 프레임 구성:
  - 0~2: 중심 반지름 60~120px의 날카로운 고리 + 바깥으로 뻗는 짧은 방사형 속도선 8~12개.
  - 3~8: 고리가 반지름 230px까지 퍼짐. 고리 앞쪽 가장자리는 밝고 뾰족한 톱니(바람에 찢긴 모양), 뒤쪽은 어둡게 빠짐.
    고리 안쪽에 회전 방향(반시계)으로 휘는 바람 갈래 3~4개.
  - 9~15: 고리가 끊어진 조각으로 흩어지며 회색으로 사라짐. 15번은 거의 빈 칸.
- 금지: 흙먼지 사진 질감, 둥근 구름 덩어리, 칸을 꽉 채운 반투명 원판.

## 5. 제출 전 자체 검수

1. 파일 이름·크기(2048/1024/2048)·RGBA 확인.
2. 알파 0이 아닌 픽셀의 RGB가 무채색(R=G=B 근처)인지 확인.
3. 각 칸 사방 16px 이내에 알파 > 0 픽셀이 없는지 확인.
4. 각 칸에서 알파 1~20의 흩어진 잡티 픽셀이 없는지 확인(있으면 지움).
5. 궤적 아틀라스: 모든 프레임에서 머리가 3시 방향, 꼬리가 시계 방향인지 확인. 밝은 날선이 반지름 약 205px인지 확인.
6. 16프레임을 GIF/연속 미리보기로 만들어 떨림·끊김이 없는지 확인. 미리보기는 실제 에셋과 별도 파일로
   `ArtPreviews/Whirlwind_20261112/`에 저장(어두운 배경 + 빨강·주황·흰색으로 임시 착색해서 게임 느낌 확인 권장).
7. 기존 파일을 덮어쓰는 경우 원본 PNG와 .meta를 `ArtBackups/`에 백업하고 .meta(GUID)는 유지.
8. 보고할 때 파일상 확인과 Unity 실제 플레이 확인을 구분한다.
