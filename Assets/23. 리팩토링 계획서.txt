0. 수업의 목적과 방식
======================================================================

목적
- 거의 완성된 게임을 처음부터 다시 만들면서, 게임의 구조와 스크립트를 직접 쓰고 이해함.
- 규칙은 20번 기획서만 따름. 21번 구현 계획서는 보지 않음.
- 전체 틀(4장)과 스크립트 목록(5장)은 처음에 다 정해 둠. 수업은 그 틀을 아래에서부터 하나씩 채우는 것.
- 지금의 게임(옛 코드)은 지우지 않고 "참고서"로 둠. 정답지가 아님: 옛 코드에는 기획과 다른 옛 규칙이 남아 있음.

한 수업의 흐름
  1. 배울 것   새로 나오는 C#·Unity 개념과 패턴. 왜 필요한지부터.
  2. 기획      20번의 몇 장을 구현하는지. 먼저 그 장을 읽음.
  3. 설계      만들 파일, 그 안의 필드와 함수, 함수가 하는 일의 순서.
  4. 직접 쓰기 사용자가 씀.
  5. 리뷰      Claude가 읽고 고칠 곳과 이유를 말함. 사용자가 고침.
  6. 확인      "확인" 칸에 적힌 방법으로 동작을 봄. 통과하면 맨 위의 "다음 수업" 번호를 올림.

막혔을 때
- 말로 된 힌트보다 거의 완성된 코드에 빈칸 한두 개를 뚫은 것을 달라고 하면 됨.
- 그래도 막히면 완성 코드에 줄마다 설명을 붙여서 보여 줌. 읽고 이해한 뒤, 같은 모양의 다음 함수는 직접 씀.
- "정답 보여 줘"라고 하면 그 부분은 Claude가 씀.

커밋은 퇴근할 때 사용자가 하루치를 한 번에 함.

2. 게임의 큰 그림 — 먼저 머릿속에 넣을 것
======================================================================

[한 판의 흐름] (20번 1장)
  판 시작 → 특수 타일 배치
  웨이브 1 ~ 40 반복:
    소환 전 판정 (남은 적 수 > 한도 → 게임 오버)
    → 이번 웨이브의 적을 한꺼번에 소환
    → 플레이어 턴 1번 (생성, 이동, 합성, 강화, 판매, 존 자리 고르기, 공격할 칸 고르기)
    → 적 턴 10번 (40웨이브는 최대 20번). 적 턴 한 번의 단계는 4장 [4-1]
  40웨이브 최종 보스 처치 → 클리어

[매니저 9개 — 씬에 하나씩, 누가 무엇의 주인인가]
  GameSession       한 판의 설정(모드·스테이지·고른 문양), 적 수 한도, 게임 오버·클리어, 문양 공유 값(어둠의 카운트)
  TurnManager       웨이브와 턴의 순서 (위의 흐름 그 자체). 턴 상태
  WaveManager       지금 몇 웨이브인가, 이번에 누구를 소환하나
  BoardManager      판의 부품: 칸의 좌표와 번호, 누가 어느 칸에 있나, 특수 타일, 존, 장판
  EnemyManager      살아 있는 적 목록, 소환, 모든 적을 차례로 처리
  TowerManager      플레이어의 타워 조작(생성·판매·이동·합성·강화)과 타워 목록
  ProjectileManager 투사체 풀과 발사
  CurrencyManager   골드와 젬
  UIManager         패널 켜고 끄기
  나머지 스크립트는 이 매니저 중 하나가 들고 있거나, 프리팹에 붙어 있거나, 상태 없는 계산임.

[스크립트를 나누는 다섯 가지 역할]
  데이터   원본 값. 판 도중 바뀌지 않음 (CSV, ScriptableObject)
  상태     판 도중 바뀌는 값. 값마다 주인이 하나
  계산     입력 → 결과만. MonoBehaviour가 아님 → 자동 테스트 가능
  진행     순서를 정함
  표현     화면. 상태를 읽기만 함
  옛 코드가 읽기 어려운 까닭이 이 다섯이 한 파일에 섞여 있어서임.
  예: 옛 TileManager(1319줄)는 좌표, 점유, 특수 타일, 효과 기록, 연출을 다 가짐. 새로 만들 때는 Board 폴더의 12개로 나뉨.

[싱글톤] — 수업 2
  씬에 하나뿐인 매니저를 어디서든 찾게 함 (TowerManager.Instance). 매니저 9개에만 씀.
  왜: 매니저는 하나뿐이고 여러 스크립트가 찾음.
  조심: 계산·상태 클래스는 싱글톤으로 만들지 않음. 필요한 값은 인자로 받아야 테스트할 수 있음.
        씬 단위. DontDestroyOnLoad 하지 않음.

[오브젝트 풀] — 수업 5, 16
  미리 만들어 둔 오브젝트를 껐다 켜며 다시 씀.
  왜: Instantiate / Destroy는 할 때마다 메모리를 새로 잡고 버림. 버린 메모리를 치우는 GC가 돌면 화면이 순간 멈춤.
      이 게임은 그 순간이 몰림: 웨이브 시작에 최대 40마리 동시 소환(한 판 일반 적 720마리), 단일 타워 한 번 행동에 수십 발.
  쓰는 곳: 적, 투사체, 이펙트, 대미지 숫자, 적 정보 패널의 목록 항목.
  안 쓰는 곳: 타워. 플레이어 턴의 조작으로만 생기고(한 판 160기 안팎) 상태가 많아, 초기화를 빠뜨릴 위험이 얻는 것보다 큼.
              더미. 적 한 마리에 하나뿐이고 수가 적음.
  조심: 풀의 가장 흔한 버그는 "지난번에 쓰던 상태가 남아 있는 것". 꺼낼 때 지울 목록을 정해 둠.

[상태 패턴] — 수업 9, 18
  "지금 무슨 상태인가"를 if로 여기저기 묻지 않고, 상태 객체가 "이 상태에서 무엇을 할 수 있는가"를 답함.
  왜: 플레이어 턴에만 생성·합성이 되고, 적 턴에도 스택 소모 버튼은 됨. 입력도 같은 클릭이 모드마다 뜻이 다름.
  쓰는 곳: 턴 상태 5종, 입력 모드 4종.
  안 쓰는 곳: 존의 단계(스킬 1 / 스킬 2 / 불길 / 충전·과충전·방전). 넷 이하라 enum으로 충분.

[옵저버 (C# event)] — 수업 10
  알리는 쪽은 "바뀌었다"고만 외치고, 듣고 싶은 쪽이 구독함. 이벤트 목록은 4장 [4-2].
  왜: CurrencyManager는 UI가 있는지 몰라도 됨. 듣는 쪽이 늘어도 알리는 쪽은 고치지 않음.
  안 쓰는 곳: 적 1턴의 순서. 이벤트로 하면 순서가 "누가 먼저 구독했나"에 숨어 버림. 이 게임은 순서가 곧 규칙이라 직접 부름.
  조심: 구독(+=)과 해제(-=)는 짝으로. 해제를 잊으면 파괴된 오브젝트를 부르다 에러.

[인터페이스] — 수업 15

[전략 패턴] — 수업 15, 17, 22, 25, 27 ~ 40

  왜: 20번 4-1장의 틀이 바로 이 모양. 모든 타워가 스킬 1과 스킬 2를 가지되 내용은 컬러·문양마다 다름.
      switch로 하면 문양 하나를 고칠 때 여러 switch를 함께 고쳐야 하고, 하나를 빠뜨려도 컴파일 에러가 나지 않음.

[4-1] 적 1턴의 단계 — TurnManager가 이 순서로 직접 부름 (20번 1장 [적 1턴의 순서])
----------------------------------------------------------------------
  ⓪ 적 턴 시작   타워: 서 있는 칸의 버프존을 다시 모음 (벗어났으면 즉시 끝). 스킬·시간 버프의 "턴 시작"
                 적: 상태 효과의 "턴 시작" (도깨비불 스택 비우기 등)
  ① 적 이동      적마다 행동 카운터 → 행동하는 적은 "다음 이동을 정할 때" 훅 → 주사위 → 이동 → "이동한 뒤" 훅
                 (상태 유지 감소, 저항 감소, 프리즘 감소, 난기류). 행동 불가(0 / 0)도 행동으로 셈
  ② 버프·디버프 타워  보드 순서로 행동력 → 존에 스택 → 단계 갱신 → 버프 전달 (확률 버프 굴림, 불길·과충전 순환)
  ③ 멈춘 칸의 효과    적마다: 디버프존 밟기(스택 + 효과) → 특수 타일(멈춰 있는 동안 / 매 턴) → 비프로스트·정화 → 회복은 마지막
                      (같은 턴에 치유 감소가 먼저 걸리게. 20번 1장 끝줄)
  ④ 공격 타워    보드 순서로 한 기씩: 행동력 → 스킬 2 발동 확인 → 기본 공격 → AttackHandle이 끝날 때까지 기다림 → 다음 타워
  ⑤ 디버프 경과  상태 효과의 "매 턴"(지속 피해, 빙결·속박 확률, 감전의 전하) → 장판 피해(화살비·블랙홀) → 장판 남은 턴 감소
  ⑥ 보스 제한 턴  보스·중간 보스마다 1 감소, 0이면 게임 오버
  적 턴 10번 뒤 → 소환 전 판정 → 다음 웨이브

[4-8] 여러 기능이 함께 동작하는지 보는 확인 (2026-10-20 추가)

계산식 테스트(T1 ~ T8)는 함수 하나만 봄. 투사체 회수, 턴 종료, 재시작처럼 여럿이 엮인 곳은 따로 확인함.
1) 항상 맞아야 하는 것 — #169 InvariantChecker가 적 턴이 끝날 때마다 검사하고 어긋나면 Debug.LogError
   - 날아가는 투사체 0, 끝나지 않은 AttackHandle 0, 돌고 있는 이동 코루틴 0
   - 켜져 있는 적 오브젝트 수 = EnemyRegistry의 수 (죽은 적이 풀로 돌아감)
   - 점유에 든 대상 수 = 살아 있는 적 수 + 더미 수, 점유의 칸 번호 = 그 대상의 PathIndex
   - 적마다 사망 이벤트는 많아야 한 번
   - 골드·젬은 음수가 아님
   - 판 위 타워 수 = TowerSlots에 든 수, 존의 주인은 모두 살아 있는 타워
   - GameLoop는 하나만 돌고 있음
2) 시나리오 — 부가 끝날 때마다 손으로 한 번씩 (DebugCheat의 자동 진행 키: 턴 종료 자동 + 배속)
   S1 연타        턴 종료 키를 빠르게 여러 번 → 적 턴이 한 번만 진행됨 (수업 9부터)

   S3 공격 중 사망  다발 공격 중 대상이 죽음 → 남은 탄은 다음 대상에게 가거나 회수되고, 턴이 멈추지 않음 (수업 16, 17)
   S4 이동 중 사망  이동 중인 적이 장판·지속 피해로 죽음 → 이동 코루틴이 남지 않음 (수업 25, 29)
   S5 실패 보호    골드 0에서 생성 / 빈 칸 없이 생성 / 재료가 모자란 합성 / 결과가 없는 합성 → 재화·재료·비용이 그대로 (수업 12, 19)
   S6 교체 뒤 정리  타워를 티어 강화·판매·합성 → 그 타워의 존·한도 보정·버프가 남지 않음 (수업 19, 26, 31, 32)
   S7 재시작       게임 오버 → 재시작 → 매니저 Instance가 하나씩, 적·타워·투사체가 0에서 시작, 이벤트 구독이 두 겹이 아님,

3) static에 판의 상태를 두지 않음

수업 5. 오브젝트 풀 — #119 EnemyPool                          [패턴: 오브젝트 풀]
----------------------------------------------------------------------
배울 것
  - UnityEngine.Pool.ObjectPool<T>: 만들기·꺼낼 때·돌려놓을 때·버릴 때 네 함수를 넘겨 줌.
  - SetActive(false / true).
  - 3장 [오브젝트 풀]을 먼저 읽음.
설계
  필드: [SerializeField] EnemyController prefab, Transform container, int defaultCapacity(40), int maxSize
        ObjectPool<EnemyController> pool
  Awake: pool = new ObjectPool<EnemyController>(만들기, 꺼낼 때, 돌려놓을 때, 버릴 때, collectionCheck: true, ...)
    만들기         Instantiate(prefab, container) 하고 바로 SetActive(false)
    꺼낼 때        아무것도 하지 않음  ← 이 프로젝트의 약속. 켜는 것은 초기화를 마친 뒤 Spawner가 함 (수업 7)
    돌려놓을 때    SetActive(false)
    버릴 때        Destroy
  EnemyController Get(), void Release(EnemyController enemy)
  종류별(일반·중간 보스·최종 보스)로 EnemyPool을 하나씩 둠
함정
  - 꺼낼 때 바로 켜면 초기화 전에 OnEnable이 돌아, 빈 데이터로 동작하는 코드가 생김.
  - 같은 적을 두 번 Release하면 collectionCheck가 에러를 냄 (일부러 켜 둠. 버그를 빨리 찾게).
  - maxSize는 "돌려받아 보관하는 수"의 한도라 Get은 실패하지 않음. 꺼낸 수를 직접 세어 막지 않음 (옛 코드는 20에서 막혀 게임이 안 끝났음. B4).
확인: 키를 누르면 40마리 Get, 다시 누르면 전부 Release. 반복해도 하이어라키의 적 오브젝트 수가 40에서 늘지 않음.
참고(옛 코드): EnemyObjectPool2D.cs (꺼낼 때 초기화까지 하는 점이 다름)

수업 6. 웨이브 표 — #10 WaveTable, T3
----------------------------------------------------------------------
배울 것
  - 계산만 하는 static 클래스를 따로 두는 이유: Unity를 켜지 않고 테스트로 표가 맞는지 확인.
  - out 매개변수로 값 둘 돌려주기.
기획: 20번 3장 [웨이브 구성], [웨이브별 능력치 배율], [중간 보스], 1장 [패배와 클리어](한도), 8장 [처치 보상], 9장 (모드 배율·한도)
설계
  int GetCycle(int wave)            1 ~ 10 → 1, 11 ~ 20 → 2 ...
  int GetOrder(int wave)            사이클 안의 순서 1 ~ 10
  int GetNormalCount(int wave)      순서 1 ~ 4: 8 × 사이클 / 5, 10: 0 / 6 ~ 9: 10 × 사이클
  bool HasMiddleBoss(int wave), bool HasBoss(int wave)
  float GetHpMultiplier(int wave, EnemyKind kind)       일반: 순서 배율 × 사이클 배율 / 보스·중간 보스: 사이클 배율만
  float GetDefenseMultiplier(int wave, EnemyKind kind)  (같은 방식)
  float GetModeStatMultiplier(GameMode mode)            스토리 0.75 / 노말 1 / 하드 1.5
  int GetEnemyLimit(GameMode mode, int cycle)           노말·스토리 20 × 사이클 / 하드 15 × 사이클
  void GetKillReward(EnemyKind kind, int spawnWave, out int gold, out int gem)   기본값만 (보정은 DeathResolver)
함정
  - 순서 배율 표의 순서 5(체력 3.0)는 일반 적이 없는 칸. 중간 보스는 사이클 배율만 받음.
  - (wave - 1)을 먼저 빼야 10, 20웨이브가 다음 사이클로 넘어가지 않음.
확인: T3 — GetNormalCount(1) == 8, GetNormalCount(16) == 20, 1 ~ 40웨이브의 일반 적 합 == 720,
      GetHpMultiplier(9, Normal) == 5.0, GetHpMultiplier(19, Normal) == 10.0, 10웨이브 보스 보상 == 1000골드 20젬.
참고(옛 코드): WaveManager.cs의 구성 부분과 GetKillReward

수업 7. 소환 — #20 PathOccupancy, #117 EnemyManager, #118 EnemySpawner, #120 EnemyRegistry, #29 BoardPresenter(적 수 표시)
----------------------------------------------------------------------
배울 것
  - 초기화 순서의 약속: 비활성 상태에서 초기화 → 위치 → 활성화 → 등록.
  - 등록과 해제를 짝으로 만들기, 밖에는 IReadOnlyList로만 보여 주기 (남이 목록을 바꾸지 못하게).
  - 매니저가 순수 클래스 부품을 만들어 들고 있는 모양 (BoardManager → PathOccupancy, EnemyManager → Registry·Spawner).
  - Random.Range(int, int)는 뒤의 수를 포함하지 않음.
기획: 20번 1장 [턴과 웨이브](전원 동시 소환), 2장 (전체 패스 인덱스 중 무작위, 한 칸 적 수 제한 없음, 먼저 온 적이 맨 위, "x N")
설계
  PathOccupancy (BoardManager가 들고 있음) — 누가 어느 길 칸에 있나
    Dictionary<int, List<EnemyController>>   (수업 15에서 EnemyController → ITarget으로 넓힘)
    Add(target, index)  리스트 끝에 붙임 (리스트[0] = 먼저 온 것 = 맨 위)
    Remove(target, index), Move(target, from, to)
    IReadOnlyList<...> GetAt(int index)
    event Action<int> CellChanged
  EnemyRegistry — 살아 있는 적 전부. Register / Unregister, IReadOnlyList Alive, int Count
  EnemyManager (매니저) — Registry와 Spawner를 만들어 들고 있음, event Action<int> CountChanged
  EnemySpawner
    IEnumerator SpawnWave(int wave)   WaveTable로 마리 수를 받아 한 마리씩:
      1. pool.Get()                    (꺼져 있음)
      2. Setup(정의, 배율)
      3. 무작위 인덱스 = Random.Range(0, PathCount)
      4. 위치를 그 칸으로
      5. SetActive(true)
      6. occupancy.Add, registry.Register
    (낙하 연출을 기다리는 것은 큐브 연출을 붙일 때 추가: 옛 EnemyMoveController.PlaySpawnDrop 참고)
