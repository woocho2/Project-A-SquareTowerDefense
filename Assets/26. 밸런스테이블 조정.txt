======================================================================
0. 목적과 원칙
======================================================================
- 게임을 화면 없이 처음부터 끝까지 여러 판 돌리고, 결과 표를 보며 CSV 수치를 맞춤.
- 계산은 유니티(이 컴퓨터의 CPU)가 함. AI는 다 끝난 뒤 요약 표만 읽고 어떤 수치를 고칠지 판단함.
    → 몇백 판을 돌려도 AI가 읽는 것은 표 몇십 줄이라 토큰이 적게 듦. 대신 시간은 유니티가 씀.
- 결과는 어림값이 아니라 실제 플레이와 같음: 적 이동 주사위, 치명, 생성 뽑기, 스킬 발동, 생성·합성·배치를 매 턴 실제로 계산. 그림과 대기만 빠짐.
- AI가 게임을 직접 돌리며 로그를 읽는 방식은 쓰지 않음 (한 판에 로그 수만 줄 → 토큰이 많이 듦).


======================================================================
1. 돌리는 법
======================================================================
  1) 3. Stage1 씬을 연다.
  2) 메뉴 Tools > 밸런스 시뮬레이션 → 창에서 판 수, 시작 시드, 난이도(씬 그대로 / 노말 / 하드), 문양 무작위, 배속(최대 100), 한 판 제한(초)을 정함.
  3) "실행" → 플레이 모드가 켜지고 판이 이어서 돌아감. 그동안 게임 화면은 꺼지고 콘솔엔 경고·오류만 나옴. 창에 "진행 중: n / N판".
  4) 다 끝나면 플레이 모드가 저절로 꺼지고 요약이 콘솔과 파일에 나옴. 중간에 그만두려면 창의 "멈춤"(그때까지의 결과로 요약).
결과 파일 (프로젝트 폴더/Balance, git에 안 올라감)
  날짜_시각_games.csv     판마다 한 줄 (결과, 도달 웨이브, 남은 적·한도, 골드·젬, 티어 분포, 합성, 티어가 처음 나온 웨이브, 칸이 막힌 웨이브, 처치, 총 피해)
  날짜_시각_towers.csv    판 × 타워 ID마다 한 줄 (기본·스킬·장판·기타 피해, 처치)
  날짜_시각_summary.txt   AI가 읽는 요약 (승률, 도달 웨이브, 패배 웨이브·이유, 합성 속도, 타워 종류별 피해 몫 ▲▼, 문양별 승률)
  simulation_settings.json  창이 쓰는 설정 (손댈 필요 없음)
AI에게 맡길 때: "Balance의 마지막 summary 봐 줘" — AI는 summary만 읽음.


======================================================================
2. 남은 것 — 속도 (연출 없는 모드)
======================================================================
1판은 코드를 거의 안 건드리고 빨리 감기만 함: 배속 100, 한 프레임 시간 상한 1초, 수직 동기 끔, 카메라 끔(Camera.main이 없어 화면 이펙트가 건너뜀), 일반 로그 끔.
먼저 한 판에 몇 초 걸리는지 잼. 너무 느리면 "시뮬레이션이면 건너뛰기"(SimulationRunner.IsOn)를 아래에 넣음 (계산 로직은 그대로).
  - 이펙트 입구: SkillEffectTable(Play·PlayCast·PlayArrowRain·PlayBlackHoleTurn), ShotEffectTable·ProjectileManager.Fire(탄은 바로 맞음)
  - 컷인: SkillCutIn.Play
  - 대기: TowerTurnRunner.WaitForVisuals(EffectActivity.WaitUntilIdle), 사격 간격 WaitForSeconds, EffectActivity.HoldFor
  - 적 이동·소환 연출(DOTween), 대미지 숫자, 합성 연출(TowerMergeEffect, 0.5초 대기)
- 더 필요하면 화면 없는 배치 모드(-batchmode -nographics -executeMethod, 에디터를 닫고)로 돌림.


======================================================================
3. 남은 것 — 기록·요약
======================================================================
1판에 없는 것 (필요해지면 더함)
  - 웨이브별 남은 적 수와 한도 (지금은 판이 끝났을 때만), 웨이브별 티어 분포
  - 스킬 2 발동 수 (피해는 스킬로 나뉘어 있음), 버프·디버프 존의 스킬 2 단계 도달 턴
  - 컬러별 승률, 이전 요약과 견준 변화(같은 시드 묶음), 문양 조합을 차례로 도는 방식
  - 피해에 빠지는 것: 즉사(집행 등 Execute)는 피해가 아니라 처치로만 셈. 맞은 적 체력보다 넘친 피해는 버림.
- 자동 플레이어(AutoPlanner.PlayStep)는 생성(돈만큼) → 합성 기다림 → 젬으로 티어·컬러 강화(젬 1당 값이 큰 것부터)
    → 칸이 꽉 차면 짝 없는 1티어 중 가장 쓸모없는 것을 팔고 다시 뽑기 → 배치 → 턴 종료. AutoPlanner의 가중치는 결과를 보며 다듬음 (2026-10-29 사용자: "나중에 테스트해보면서 밸런스랑 맞춰보는걸로").


======================================================================
4. 남은 것 — 확인
======================================================================
  - 같은 시드로 두 번 돌려 games.csv 줄이 같은지 (같은 시드 = 같은 판이어야 수치 전후를 견줄 수 있음)
    다르면: 프레임 시간에 따라 순서가 바뀌는 곳이나 연출 쪽의 UnityEngine.Random(예: 테두리 반짝임 시작 시각)을 찾아 System.Random으로 바꿈
  - "멈춤·시간 초과"(Stuck·Timeout) 판이 나오는지: 놓을 칸이 없는 존, 끝나지 않는 대기
  - 한 판에 걸리는 시간 (2번)
  - 시뮬레이션이 끝난 뒤 보통 플레이가 평소대로인지 (배속·로그·카메라가 돌아왔는지)


======================================================================
5. 조정 반복
======================================================================
  1) 목표를 정함 (7번)
  2) 바꿀 수치를 고름 → CSV(또는 코드 상수)를 고침
  3) 같은 시드 묶음으로 N판 돌림 (예: 50판)
  4) 요약을 보고 목표와 견줌 → 2)로
- 한 번에 바꾸는 수치는 적게 (무엇이 효과를 냈는지 알 수 있게).
- 바꾼 수치와 그 이유, 전후 요약 수치는 22번 리팩토링 내역서에 적음.


======================================================================
6. 지킬 것
======================================================================
- CSV는 사용자가 허락한 범위만 고침 (사용자: "csv는 냅두라고" — 밸런스 조정을 시작할 때 범위를 다시 정함).
- 기획(20번)의 규칙·식은 바꾸지 않음. 숫자만 맞춤. 규칙을 바꿔야 할 것 같으면 사용자에게 먼저 물음.
- 시뮬레이션은 보통 플레이에 영향이 없어야 함 (설정 파일이 꺼져 있으면 SimulationRunner가 생기지 않음).
- 3. Scripts의 새 스크립트는 맨 위 한 줄 설명 말고 주석 없음, 안 쓰는 using 없음 (24번).
