======================================================================
0. 목적과 원칙
======================================================================
- 게임을 화면 없이 처음부터 끝까지 여러 판 돌리고, 결과 표를 보며 CSV 수치를 맞춤.
- 계산은 유니티(이 컴퓨터의 CPU)가 함. AI는 다 끝난 뒤 요약 표만 읽고 어떤 수치를 고칠지 판단함.
    → 몇백 판을 돌려도 AI가 읽는 것은 표 몇십 줄이라 토큰이 적게 듦. 대신 시간은 유니티가 씀.
- 결과는 어림값이 아니라 실제 플레이와 같음: 적 이동 주사위, 치명, 생성 뽑기, 스킬 발동, 생성·합성·배치를 매 턴 실제로 계산. 그림과 대기만 빠짐.
- AI가 게임을 직접 돌리며 로그를 읽는 방식은 쓰지 않음 (한 판에 로그 수만 줄 → 토큰이 많이 듦).


======================================================================
1. 돌리는 법
======================================================================
  1) 3. Stage1 씬을 연다.
  2) 메뉴 Tools > 밸런스 시뮬레이션 → 창에서 판 수, 시작 시드, 난이도(씬 그대로 / 노말 / 하드), 문양 무작위, 배속(최대 100), 한 판 제한(초)을 정함.
  3) 합성 비교는 "합성 A/B 비교"를 켜고 A=3기, B=2기로 정한 뒤 "A/B 실행". 같은 시드의 A → B를 반복하며, 조건당 20판이면 총 40판.
     단일 설정은 비교를 끄고 "실행" → 플레이 모드가 켜지고 판이 이어서 돌아감. 그동안 게임 화면은 꺼지고 콘솔엔 경고·오류만 나옴. 창에 "진행 중: n / N판".
  4) 다 끝나면 플레이 모드가 저절로 꺼지고 요약이 툴 창·콘솔·파일에 나옴. "현재/마지막 결과 보기"는 중간 결과 갱신, "결과 복사"는 표시된 요약을 복사. 중간에 그만두려면 창의 "멈춤"(그때까지의 결과로 요약).
결과 파일 (프로젝트 폴더/Balance, git에 안 올라감)
  날짜_시각_games.csv     판마다 한 줄 (결과, 도달 웨이브, 남은 적·한도, 골드·젬, 티어 분포, 합성, 티어가 처음 나온 웨이브, 칸이 막힌 웨이브, 처치, 총 피해)
  날짜_시각_towers.csv    판 × 타워 ID마다 한 줄 (기본·스킬·장판·기타 피해, 처치)
  날짜_시각_summary.txt   AI가 읽는 요약 (승률, 도달 웨이브, 패배 웨이브·이유, 합성 속도, 타워 종류별 피해 몫 ▲▼, 문양별 승률)
  A/B 비교는 각 조건의 _A_games.csv / _B_games.csv와 타워 CSV·요약을 따로 저장.
  날짜_시각_comparison.txt  같은 시드의 정상 완료 짝 비교(클리어율, 웨이브, 골드·젬, 합성 등)
  날짜_시각_paired.csv      짝별 원자료. 제외된 짝은 valid_pair=0
  simulation_settings.json  창이 쓰는 설정 (손댈 필요 없음)
AI에게 맡길 때: "Balance의 마지막 summary 봐 줘" — AI는 summary만 읽음.
[덱별 실전 화력 비교]
- Unity 에디터를 닫고 프로젝트 루트 PowerShell에서 실행:
& "C:\Program Files\Unity\Hub\Editor\6000.3.9f1\Editor\Unity.exe" -batchmode -nographics -projectPath "$PWD" -executeMethod SquareTD.BalanceSimulationWindow.RunBatch -simDeckRanking -simRuns 100 -simSeed 1 -logFile "$PWD\Balance\deck_200_unity.log"
- 시드별 노말 4문양 → 하드 6문양을 반복. 모드당 100판이면 총 200판. 일반 플레이의 문양 수 규칙은 변경하지 않음.
- 문양은 시드별로 무작위 선택. 합성은 현재 기본 3기, 자동 소환·판매·합성·젬 강화·배치는 기존 AutoPlanner.
- 화력은 초당 피해가 아니라 타워 1기당 적 턴당 피해(DPT): 피해 합계 / 배치된 타워 기수×적 턴.
  공격 대기와 사거리 밖 대기도 분모에 포함. 기본·스킬·장판·기타를 나누고, 출전 판 수를 표시.
- *_dpt_summary.txt: 모드별 전체 티어 합산 순위. *_dpt_ranking.csv: tier=0 합산, tier=1~5 동일 티어 순위.
  일반 모드별 games/towers/summary 파일도 보존. Timeout/Stuck 등 미완료 판은 화력 표에서 제외.
- 기존 towers.csv에 tower_turns 열 추가. 적 턴 시작 시 실제 배치된 타워를 세므로, 종결 턴도 분모에 포함.
- 같은 시드는 시작 상태를 맞추는 것. 게임·연출의 전역 난수 공유와 프레임 차이까지 고정한 재현성은 아직 미확보.
- CSV SHA256을 시작 설정에 저장하고 완료 후 현재 파일과 대조. Power·AbilityValue 임시값 기준의 실전 표본임을 명시.


[백그라운드 A/B 실행 — 에디터 창 없이]
  1) Unity에서 저장하고 에디터를 종료. 같은 프로젝트를 열어 둔 에디터와 배치 프로세스는 함께 실행할 수 없음.
  2) VS Code에서 프로젝트 루트 폴더를 열고 PowerShell 터미널에 아래를 입력.
& "C:\Program Files\Unity\Hub\Editor\6000.3.9f1\Editor\Unity.exe" -batchmode -nographics -projectPath "$PWD" -executeMethod SquareTD.BalanceSimulationWindow.RunBatch -simRuns 20 -simSeed 1 -simMergeA 3 -simMergeB 2 -logFile "$PWD\Balance\batch_unity.log"
  3) A=3기, B=2기, 시드 1부터 조건당 20판(총 40판). -simRuns를 바꾸면 조건당 판 수를 변경.
     난이도·문양 무작위·배속·한 판 제한은 툴의 마지막 저장 설정을 사용.
  4) Balance/batch_*_comparison.txt와 조건별 CSV에 결과 저장 후 자동 종료. 로그는 Balance/batch_unity.log.
     현재 진행 수는 Balance/simulation_settings.json의 Finished, 전체 판 수는 Runs*2로 확인.
  - -quit를 추가하면 비동기 시뮬레이션이 끝나기 전에 종료될 수 있으므로 붙이지 않음.
  - RunBatch 진입·인자 검증·장면 열기·결과 저장 후 종료 연결은 컴파일 확인. 실제 배치 완주·속도 검증은 아직.

2. 남은 것 — 속도 (연출 없는 모드)
======================================================================
현재는 스킬 컷인을 시뮬레이션에서 생략하며, 나머지는 빨리 감기 위주: 배속 100, 한 프레임 시간 상한 1초, 수직 동기 끔, 카메라 끔(Camera.main이 없어 화면 이펙트가 건너뜀), 일반 로그 끔.
먼저 한 판에 몇 초 걸리는지 잼. 너무 느리면 "시뮬레이션이면 건너뛰기"(SimulationRunner.IsOn)를 아래에 넣음 (계산 로직은 그대로).
  - 이펙트 입구: SkillEffectTable(Play·PlayCast·PlayArrowRain·PlayBlackHoleTurn), ShotEffectTable·ProjectileManager.Fire(탄은 바로 맞음)
  - 대기: TowerTurnRunner.WaitForVisuals(EffectActivity.WaitUntilIdle), 사격 간격 WaitForSeconds, EffectActivity.HoldFor
  - 적 이동·소환 연출(DOTween), 대미지 숫자, 합성 연출(TowerMergeEffect, 0.5초 대기)

3. 남은 것 — 기록·요약
======================================================================
1판에 없는 것 (필요해지면 더함)
  - 웨이브별 남은 적 수와 한도 (지금은 판이 끝났을 때만), 웨이브별 티어 분포
  - 스킬 2 발동 수 (피해는 스킬로 나뉘어 있음), 버프·디버프 존의 스킬 2 단계 도달 턴
  - 컬러별 승률, 이전 요약과 견준 변화(같은 시드 묶음), 문양 조합을 차례로 도는 방식
  - 피해에 빠지는 것: 즉사(집행 등 Execute)는 피해가 아니라 처치로만 셈. 맞은 적 체력보다 넘친 피해는 버림.
- 자동 플레이어(AutoPlanner.PlayStep)는 생성(돈만큼) → 합성 기다림 → 젬으로 티어·컬러 강화(젬 1당 값이 큰 것부터)
    → 칸이 꽉 차면 짝 없는 1티어 중 가장 쓸모없는 것을 팔고 다시 뽑기 → 배치 → 턴 종료. AutoPlanner의 가중치는 결과를 보며 다듬음 (2026-10-29 사용자: "나중에 테스트해보면서 밸런스랑 맞춰보는걸로").

4. 남은 것 — 확인
======================================================================
  - 같은 시드로 두 번 돌려 games.csv 줄이 같은지 (같은 시드 = 같은 판이어야 수치 전후를 견줄 수 있음)
    다르면: 프레임 시간에 따라 순서가 바뀌는 곳이나 연출 쪽의 UnityEngine.Random(예: 테두리 반짝임 시작 시각)을 찾아 System.Random으로 바꿈
  - "멈춤·시간 초과"(Stuck·Timeout) 판이 나오는지: 놓을 칸이 없는 존, 끝나지 않는 대기
  - 한 판에 걸리는 시간 (2번)
  - 시뮬레이션이 끝난 뒤 보통 플레이가 평소대로인지 (배속·로그·카메라가 돌아왔는지)

6. 지킬 것
======================================================================
- CSV는 사용자가 허락한 범위만 고침. 확정 범위는 일반 공격 레드·블루 140행의 Range·Action·AttackCount·CriticalRate·CriticalDamage·Stack·Duration·ProjectileSpeed (20번 10장).
  Power·AbilityValue는 보류. 버프·디버프 행과 나머지 열은 이번 적용 범위 밖.
- 기획(20번)의 규칙·식은 바꾸지 않음. 숫자만 맞춤. 규칙을 바꿔야 할 것 같으면 사용자에게 먼저 물음.
- 시뮬레이션은 보통 플레이에 영향이 없어야 함 (설정 파일이 꺼져 있으면 SimulationRunner가 생기지 않음).
- 3. Scripts의 새 스크립트는 맨 위 한 줄 설명 말고 주석 없음, 안 쓰는 using 없음 (24번).

8. 지켜볼 것
======================================================================
[합성이 빡빡함] (2026-10-29 사용자: "몇판 돌려보니까, 합성이 좀 빡세긴 하더라고 … 예의주시해야")
  - 지금 합성 규칙: 같은 타워(같은 ID) 3기가 모이면 자동 합성 (20번 8장 [합성]).
    1티어 생성은 고른 문양(노말 6) × 컬러 4 = 24종 중 무작위라 같은 타워 3기가 잘 안 모이고, 스폰 칸(약 20칸)이 먼저 참.
  - 볼 수치 (summary [합성]): 티어 2 ~ 5·시너지가 처음 나온 평균 웨이브, 판당 합성 횟수, 칸이 꽉 차서 생성을 못 한 웨이브
  - 판단: 위 수치가 웨이브 난도를 못 따라가 패배가 몰리면 합성을 손볼 후보로 올림.
  - 손볼 수 있는 것 (후보일 뿐, 고르지 않음): 생성 비용·증가폭, 판매 보상, 스폰 칸 수, 생성 뽑기 방식, 합성에 필요한 수.
    이 가운데 규칙(뽑기 방식, 필요한 수, 칸 수)을 바꾸는 것은 기획 변경이라 사용자에게 먼저 물음 (6번).

9. 활·창·얼음·불 고정 덱 배치 비교 (2026-10-29)
======================================================================
- 사용자 선택: 활·창의 찌르기 추가 효과를 함께 보기 위해 활·창·얼음·불 4문양, 노말로 고정.
- 기존 자동 배치 + 맵/버프/디버프 순서 6개. 개선 정책은 우선순위 가중치 4:2:1.
  구매·합성3기·강화·판매 정책과 CSV는 유지하고, 각 시드에 7개 정책을 교차 실행.
- 목표 표본: 전략당100판, 시드1~100, 총700판. 모든 전략이 정상 종료한 공통 시드만 비교.
  정렬은 평균 생존 적 턴 → 도달 웨이브 → 처치 수.
- AutoPlanner: 현재 존 단계의 실제 버프 수식, 활·창 찌르기 보너스, 정화 제외,
  현재 적 위치·다음 이동 후보·공격 범위와 특수 타일을 평가. 가중치 행렬의 자리 배정은 최대 합 배정.
  전체 배치 전역 최적해가 아니라 6개 휴리스틱 정책의 실전 비교.
- 이번 배치 모드에만 맵 시드 고정, 장식 난수 억제, 게임 시간1/30초 고정 간격 사용.
  배치 실행에서는 Canvas 렌더링만 비활성. 일반 플레이·기존 A/B 및 덱 화력 모드에는 이 통제를 강제하지 않음.
- 같은 정책을 같은 시드로 반복한40판(기존/정책1 각각10쌍)의 게임·타워·웨이브별 배치 기록 일치.
  Canvas 억제 전후8판의 동일 시드 기록도 일치. unscaled_delta는 실제 실행 시간이라 비교에서 제외.
  전략을 바꾸면 행동과 합성이 달라져 이후 난수 소비 순서는 달라질 수 있음.
