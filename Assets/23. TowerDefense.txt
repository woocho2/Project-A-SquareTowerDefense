================================================================================
0. 문서 목적
================================================================================

이 문서는 현재 프로젝트의 코드 문제, 리팩토링 방향, 권장 작업 순서를 한곳에서 확인하기 위한 기준 문서다.

- 타워, 게임 흐름, 웨이브, 적, 투사체, 타일, UI, 로딩, 이펙트, 공통 코드
- 정적 코드와 호출 흐름 기준 검토

검토 제외:

- 외부 에셋 내부 구현
- Unity 플레이 모드에서의 실제 재현 테스트

- 아래 내용은 코드상 확인된 문제이며 아직 실제 수정하지 않음


================================================================================
1. 전체 결론
================================================================================

리팩토링 필요도는 높다.

가장 큰 문제는 단순히 파일이 크거나 성능이 나쁜 것이 아니다. 동일한 상태를 여러 객체가 따로 보유하고, 옛 시스템과 새 시스템이 동시에 남아 있어 하나의 규칙을 고쳤을 때 다른 시스템의 결과까지 흔들리는 구조가 핵심 문제다.

현재 우선 해결해야 할 축은 다음과 같다.

1) 생명력, 웨이브, 사망 같은 핵심 상태의 소유자를 하나로 만든다.
2) 타일 기반 버프/디버프와 옛 직접 버프/디버프 시스템을 하나로 통일한다.
3) 버프 적용, 공격, 이동, 타일 효과 발동의 턴 순서를 명확히 분리한다.
4) TowerManager, UIManager, TileManager, ProjectileHit2D의 과도한 책임을 나눈다.
5) 리팩토링 전 최소한의 EditMode/PlayMode 회귀 테스트를 만든다.

전면 재작성은 권장하지 않는다. 현재 잘 작동하는 Dictionary 기반 타일 판정, 공격 Action 분리, 오브젝트 풀, 순차 코루틴 연출은 유지하면서 단계적으로 정리하는 것이 안전하다.


================================================================================
2. P0 — 먼저 고쳐야 할 실제 동작 오류
================================================================================

P0는 리팩토링보다 먼저 수정해야 하는 항목이다. 실제 게임 결과가 틀리거나 예외, 중복 보상, 진행 불능으로 이어질 수 있다.


2-1. 생명력과 게임오버가 GameManager/UIManager에 이중으로 존재한다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyMoveController.cs:319
- Assets/3. Scripts/04. Manager/GameManager.cs:276
- Assets/3. Scripts/04. Manager/UIManager.cs:903
- Assets/3. Scripts/04. Manager/UIManager.cs:1346

현재 적이 도착점에 도달하면 다음 처리가 모두 실행된다.

- GameManager.DecreaseLife(1): 실제 생명력과 실드를 계산한다.
- UIManager.OnPlayerHit(...): UIManager의 currentLifeIndex를 별도로 감소시킨다.

발생 가능한 문제:

- 실드가 피해를 전부 막아도 하트 UI는 줄어든다.
- GameManager 생명력은 20인데 하트 이미지가 3개라면 세 번째 피격에 UI만 게임오버가 된다.
- UIManager.ShowGameOver()는 패널과 일시정지만 처리하고 GameManager의 TurnState를 GameOver로 바꾸지 않는다.
- 실제 게임 상태와 표시 상태가 서로 달라진다.

권장 수정:

- 생명력, 실드, 게임오버 판정은 GameManager 또는 GameSession 하나만 소유한다.
- DecreaseLife()는 실제 적용 피해량과 남은 생명력을 반환하거나 OnLifeChanged 이벤트를 발행한다.
- UI는 전달받은 값만 표시한다.
- 보스 도착도 UIManager를 직접 호출하지 않고 GameManager.OnGameOver() 한 경로만 사용한다.


2-2. 최종 보스 처치가 GameClear 상태로 전환되지 않는다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/04. Manager/WaveManager.cs:243
- Assets/3. Scripts/04. Manager/UIManager.cs:1388
- Assets/3. Scripts/04. Manager/GameManager.cs:357

WaveManager는 40웨이브 보스가 죽으면 UIManager.ShowGameClear()를 직접 호출한다. 이 경로는 화면만 멈추고 GameManager.CurrentState를 GameClear로 바꾸지 않는다.

권장 수정:

- WaveManager는 GameManager.OnGameClear()만 호출한다.
- UI는 GameManager의 상태 변경 이벤트를 받아 결과 패널을 표시한다.


2-3. 웨이브가 살아 있는 적이 아니라 소환 횟수만 기준으로 끝난다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/04. Manager/GameManager.cs:98
- Assets/3. Scripts/04. Manager/WaveManager.cs:79

현재 EnemyWaveRoutine은 웨이브 구성 수만큼 적 턴을 실행한 뒤 살아 있는 적 수와 관계없이 NextWave()를 호출한다.

특히 40웨이브 보스가 살아 있어도 41웨이브로 넘어간다. 41웨이브부터 GetWaveEnemyComposition()은 빈 목록을 반환하므로 적 턴이 0회가 되어 남은 적과 타워 모두 행동하지 못할 수 있다.

권장 수정:

- 웨이브 상태를 SpawnCount, SpawnCursor, ActiveEnemyCount, IsSpawnComplete로 나눈다.
- 모든 소환 완료와 활성 적 0을 모두 만족해야 웨이브 완료로 판정한다.
- 최종 웨이브가 끝나면 NextWave()를 호출하지 않는다.


2-4. 탈출한 적은 WaveManager의 활성 적 수에서 빠지지 않는다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyMoveController.cs:319
- Assets/3. Scripts/03. Enemy/EnemyHealthController.cs:115
- Assets/3. Scripts/04. Manager/WaveManager.cs:243

사망한 적만 WaveManager.OnEnemyDied()를 호출한다. 도착점으로 탈출한 적은 생명력을 감소시키고 풀로 돌아가지만 m_activeEnemyCount는 그대로 남는다.

권장 수정:

- OnEnemyDied 대신 EnemyExited(EnemyExitReason reason) 공통 종료 경로를 만든다.
- 종료 이유는 Killed, Escaped, ForcedDespawn 정도로 구분한다.
- 활성 적 수 감소, TilePath 해제, EnemyManager 해제, 풀 반환을 하나의 생명주기에서 실행한다.


2-5. 적 사망 처리가 재진입해 보상과 풀 반환이 중복될 수 있다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyHealthController.cs:77
- Assets/3. Scripts/03. Enemy/EnemyHealthController.cs:109
- Assets/3. Scripts/03. Enemy/EnemyDebuffController.cs:123

치명타 도중 창 디버프 즉사 조건을 만족하면 ExecuteInstantKill()이 먼저 Die()와 ReturnToPool()을 실행한다. 그러나 원래 ApplyDamage()가 계속 진행되면 다시 Die()를 호출할 수 있다.

가능한 결과:

- 골드/보석 중복 지급
- 활성 적 수 중복 감소
- ObjectPool 중복 Release 예외
- 처치 알림 중복

권장 수정:

- EnemyHealthController에 m_isDead 또는 LifeState를 둔다.
- TryDie()를 멱등 처리해 최초 한 번만 성공하도록 만든다.
- RegisterCriticalHit() 후 적이 죽었다면 ApplyDamage()를 즉시 종료한다.


2-6. 불 디버프 사망 중 Dictionary가 비워진 뒤 같은 키를 읽을 수 있다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyDebuffController.cs:104

RefreshTileDebuffs()에서 불 장판의 즉시 피해로 적이 죽으면 풀 반환 과정에서 ClearAllDebuffs()가 m_states를 비운다. 그 직후 m_states[effect.Target]를 다시 읽으면 KeyNotFoundException이 발생할 수 있다.

권장 수정:

- ApplyZoneStack()이 처리 결과와 생성된 상태를 반환하게 한다.
- 피해 후 CurrentHP와 activeInHierarchy를 다시 검사한다.
- Dictionary 인덱서 대신 TryGetValue를 사용한다.


2-7. 같은 적 턴에 힐 타일이 두 번 적용될 수 있다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyMoveController.cs:164
- Assets/3. Scripts/03. Enemy/EnemyMoveController.cs:202
- Assets/3. Scripts/04. Manager/EnemyManager.cs:70
- Assets/3. Scripts/04. Manager/GameManager.cs:188

적 이동 완료 시 CheckAndApplyTileBuff()를 실행하고, 모든 적 이동이 끝난 뒤 ProcessTileBuffs()가 같은 함수를 다시 실행한다. 힐 타일은 최대 체력의 20%를 즉시 회복하므로 한 턴에 두 번 회복할 수 있다.

권장 수정:

- 이동 코드는 위치와 TilePath 등록까지만 담당한다.
- 타일 효과 적용은 명시적인 TileResolution 단계에서 한 번만 실행한다.
- 즉시 효과와 지속 상태 갱신을 분리한다.


2-8. 불 디버프도 첫 적용 턴에 두 번 피해를 줄 가능성이 있다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyDebuffController.cs:48
- Assets/3. Scripts/03. Enemy/EnemyDebuffController.cs:188

새 불 스택 적용 시 즉시 최대 체력 비례 피해를 주고, 같은 적 턴의 AdvanceDebuffTurn()에서 다시 피해를 준다.

확인할 기획:

- 의도가 즉시 피해 + 턴 종료 틱이라면 유지한다.
- 한 턴에 한 번만 피해를 주려는 의도라면 최초 적용 턴의 틱을 건너뛰어야 한다.


2-9. 타일 방어 버프와 해머 디버프가 서로 덮어쓴다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyMoveController.cs:275
- Assets/3. Scripts/03. Enemy/EnemyMoveController.cs:306
- Assets/3. Scripts/03. Enemy/EnemyDebuffController.cs:248
- Assets/3. Scripts/03. Enemy/EnemyHealthController.cs:159

EnemyHealthController에는 m_defendMultiplier 하나만 있다. 방어 타일은 1.2를 쓰고 해머 디버프는 1보다 작은 값을 쓴다. 마지막 실행자가 이전 효과를 없앤다.

비슷한 위험이 행동력과 주사위 보정에도 존재한다.

권장 수정:

- base 값과 modifier 출처를 분리한다.
- FinalDefend = baseDefend × tileDefenseMultiplier × debuffDefenseMultiplier 형태로 계산한다.
- 확장을 고려하면 source/type이 있는 StatModifier 목록을 사용한다.


2-10. 현재 타일 디버프 경로에서는 창 누적 피해가 사라질 수 있다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/03. Enemy/EnemyDebuffController.cs:150

창 PendingDamage 정산은 RemainingDuration < 0인 레거시 경로에서만 동작한다. 현재 TileManager가 만든 디버프는 양수 duration을 가지므로 0이 되면 먼저 제거되고 누적 피해를 지급하지 않을 수 있다.

EndZoneDebuff()도 현재 호출자가 없다.

권장 수정:

- 창 상태를 OnTile, GracePeriod, Resolve, Expired처럼 명시적인 단계로 만든다.
- 일반 duration 만료와 창 누적 피해 정산 순서를 분리한다.
- TileExit 이벤트에 연결하지 않을 것이라면 EndZoneDebuff()를 제거한다.


2-11. 타워 치명타에서 거리 비례 피해가 사라진다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/01. Tower/01. TowerAttackAction/TargetAttackAction.cs:75
- Assets/3. Scripts/01. Tower/01. TowerAttackAction/SplashAttackAction.cs:73

먼저 거리 피해를 계산한 뒤 치명타가 발생하면 calculatedDamage를 기본 공격력 기준으로 다시 대입한다. 따라서 활 계열 거리 보너스가 치명타에는 적용되지 않는다.

권장 피해 파이프라인:

기본 Power
→ 거리 보정
→ 치명타 보정
→ 방어력/관통 계산
→ 최종 피해

추가로 CriticalRate가 0일 때도 Random.Range(...) <= 0 비교 때문에 극히 드물게 치명타가 발생할 수 있다. 비교는 <가 적절하다.


2-12. 타워 생성 실패 후에도 돈과 보드 상태가 변경될 수 있다
--------------------------------------------------------------------------------

관련 위치:

생성된 프리팹에 TowerController가 없어도 오류만 출력하고 이후 로직이 계속 진행될 수 있다. null Controller 정보 등록과 골드 차감으로 이어질 수 있다.

중간에 실패하면 임시 오브젝트만 제거하고 기존 상태는 유지해야 한다.


2-13. 합성 실패 시 재료 타워가 이미 삭제된 상태가 될 수 있다
--------------------------------------------------------------------------------

관련 위치:

현재 합성은 재료를 먼저 제거한 뒤 결과물을 생성한다. 결과 프리팹이나 Init에 문제가 생기면 재료를 복구할 수 없다.

권장 순서:

2-14. 디버프 타워 이동 후 디버프 존 기준 위치가 갱신되지 않는다

2-15. targetLayer 설정이 실제 타겟 탐색에 사용되지 않는다

2-16. 버프 타워 행동 순서에 따라 같은 턴의 공격 결과가 달라진다
--------------------------------------------------------------------------------

관련 위치:

- Assets/3. Scripts/01. Tower/TowerManager.cs:395
- Assets/3. Scripts/01. Tower/01. TowerAttackAction/BuffAction.cs:31

타워가 좌표 순서로 행동하므로 공격 타워가 버프 타워보다 먼저 행동하면 이번 턴 버프를 받지 못하고, 반대 순서면 받는다.

권장 턴 단계:

1) 기존 버프 duration 갱신
2) 모든 버프/디버프 타워 행동

3-1. SplashRadius의 정확한 의미
--------------------------------------------------------------------------------

현재 구현:

- SplashRadius 2 = 3×3
- SplashRadius 3 = 5×5

기획의 기본값 1이 주변 1칸, 즉 3×3을 뜻한다면 현재 구현은 한 칸 밀려 있다.


3-2. 투사체가 실제 피해의 조건인지 시각 효과인지
--------------------------------------------------------------------------------

현재는 투사체가 생성되지 않거나 도착 전 수명이 끝나면 피해도 발생하지 않는다.

선택지:

A. 시뮬레이션 방식: 투사체 명중 순간 실제 피해 적용
B. 연출 방식: 공격 판정은 즉시 확정하고 투사체는 시각 표현만 담당

현재 게임의 순차 공격 연출을 고려하면 A도 가능하지만, 풀 부족과 수명 종료가 게임 밸런스를 바꾸지 않도록 실패 정책이 필요하다.


3-3. 체력 많은 적 우선순위에서 보스 우선 여부
--------------------------------------------------------------------------------

현재는 보스를 발견하면 체력 비교 없이 먼저 선택한다. 체력 1인 보스가 체력 1,000인 일반 적보다 우선될 수 있다.

관련 위치:

- Assets/3. Scripts/01. Tower/01. TowerAttackAction/TowerAttackAction.cs:137

보스 강제 우선이 기획이면 이름을 BossFirst로 분리하고, 순수 체력 우선이라면 동일 비교 규칙을 적용해야 한다.


3-4. 불 디버프 첫 턴 처리
--------------------------------------------------------------------------------

- 장판 진입 즉시 피해 + 같은 턴 지속 피해
- 또는 첫 턴 총 1회 피해

둘 중 하나로 확정해야 한다.


3-5. GameManager의 씬 간 유지 여부
--------------------------------------------------------------------------------

- 전투마다 초기화할 경우 DontDestroyOnLoad 제거
- 월드 전체 세션을 유지할 경우 명시적인 ResetSession과 씬 서비스 재연결 필요


3-6. 타워 데이터의 진짜 원본
--------------------------------------------------------------------------------

현재 런타임 CSV 로드와 TowerCSVToSOImporter가 함께 존재한다.

선택지:

A. CSV를 유일한 원본으로 유지하고 빌드 전에 검증된 런타임 데이터로 변환
B. CSV는 편집용으로만 쓰고 생성된 ScriptableObject를 런타임 원본으로 사용

현재 프로젝트 흐름에는 A가 조금 더 자연스럽지만 둘 중 하나만 선택해야 한다.

현재 CSV 처리에서 함께 고칠 부분:

- TowerCSVtoSOimporter는 values.Length < 9만 검사한 뒤 values[18]까지 접근하므로 열이 부족한 CSV에서 예외가 날 수 있다.
- 런타임 로더와 Importer 모두 단순 Split(',')를 사용하므로 이름이나 설명에 쉼표가 들어가면 열이 깨진다.
- float.Parse/int.Parse가 실행 환경의 문화권 설정에 영향을 받을 수 있다.
- 최소 열 수 20/21 검증, InvariantCulture, 명시적인 CSV 파서를 사용하는 편이 안전하다.

4-3. Tower Action
--------------------------------------------------------------------------------

현재 SplashAttackAction, TargetAttackAction, BuffAction, DebuffAction으로 공격 방식을 나눈 방향은 좋다.

하지만 bool ExecuteAction()만으로는 비동기 공격 완료를 표현할 수 없어 상위 매니저가 전역 투사체를 감시한다.

권장 형태:

ITowerAction
  - CanExecute(TowerActionContext)
  - Execute(TowerActionContext): IEnumerator 또는 실행 핸들 반환
  - OnTowerMoved(from, to)
  - Dispose()

Action이 자신의 위성 생성, 투사체 완료, 디버프 존 이벤트 해제를 책임지면 상위 스케줄러가 구체 구현을 알 필요가 없다.


4-4. GameManager와 턴 진행

현재 GameManager는 다음을 함께 가진다.

- 실드
- 게임 속도와 일시정지
- 웨이브 미러 값
- 게임오버/클리어

추가 문제:

권장 분리:

4-9. TilePath
--------------------------------------------------------------------------------

좋은 점:

- Collider가 아닌 패스 인덱스와 좌표를 실제 판정 기준으로 사용한다.
- 이동 중 예약 목록과 도착 적 목록을 분리한다.
- 스플래시와 타겟 탐색이 동일한 데이터 원본을 사용한다.

개선점:

- GetEnemiesInSquare()와 GetAllActiveEnemies()가 호출마다 새 List를 만든다.
- LateUpdate에서 매 적마다 TryGetComponent를 호출한다.
- RegisterEnemyAtIndex()가 이전 위치를 찾기 위해 모든 버킷을 순회한다.
- 빈 Dictionary List를 제거하지 않는다.
- pathGridPositions가 public mutable List다.
- 싱글턴 중복 방어가 없다.

권장 수정:

- NonAlloc 조회 API
- EnemyHealth ↔ EnemyMovement 캐시
- enemy → currentPathIndex 역인덱스
- private serialized path + IReadOnlyList

- 클릭마다 항목을 Destroy/Instantiate한다.
- Content 높이는 Mathf.Max로만 늘어나 짧은 목록으로 바뀌어도 줄지 않는다.
- 열린 상태에서 타일 효과가 바뀌면 자동 갱신되지 않는다.

권장 수정:

- 항목 View 재사용 또는 작은 풀
- 매 갱신 시 정확한 Content 높이 재계산
- TileEffectChanged 이벤트 구독

추가 확인:

- m_btnNextStage는 이름과 달리 현재 OnQuitGame()에 연결되어 있다. 실제 다음 스테이지 이동 버튼이라면 SceneTransitionService를 호출하도록 분리해야 한다.


4-12. UIStageThemeController
--------------------------------------------------------------------------------

현재 _bg, _frame, TurnEnd, CreateTower, CTxt_ 같은 이름 문자열로 UI 역할을 추론한다.

문제:

- 오브젝트 이름을 바꾸면 조용히 테마 적용이 빠진다.
- 모든 텍스트 대비색을 실제 배경이 아닌 스테이지 전역 bgColor 기준으로 계산한다.
- ExecuteAlways와 OnValidate가 씬/프리팹을 자동 변경한다.
- Editor AssetDatabase 경로와 런타임 테마 적용이 한 파일에 있다.

권장 수정:

- RealmThemeDefinition ScriptableObject
- ThemeTarget 컴포넌트로 Background, Frame, HighButton 등을 명시
- PreserveOriginalTextColor 플래그
- Editor 기본 에셋 연결은 Editor 전용 코드로 분리


4-13. LoadingManager와 SceneLoader
--------------------------------------------------------------------------------

확인된 문제:

- SceneLoader.StartLoad()의 LoadingScene 전환이 주석 처리되어 있다.
- LoadingManager의 m_testMode 기본값이 true다.
- 실제 비동기 로딩 루프에서 UpdateUI()를 호출하지 않아 진행 바가 갱신되지 않는다.
- m_percentText는 할당되지만 사용되지 않는다.
- m_LoadingImage1/2를 검사하지만 같은 m_fadeGroup만 조절한다.
- CoFade(0, 0, 1.5)는 시각 변화가 없다.
- UIManager_Menu에 같은 CanvasGroup 페이드 코드가 중복되어 있다.

권장 수정:

- SceneTransitionService 하나로 StartLoad → LoadingScene → AsyncLoad → Activate 흐름 완성
- 테스트 모드를 별도 디버그 옵션으로 분리
- CanvasGroupFader 공통화
- 실제 진행률과 연출용 표시 진행률 분리


4-14. TileSatelliteOrbiter와 이펙트
--------------------------------------------------------------------------------

TileSatelliteOrbiter는 약 813줄이며 다음을 모두 처리한다.

- 공전 위치
- 원근 스케일
- Sorting
- 색상과 밝기
- Trail/Particle 생성
- 디버프 심볼
- Editor OnValidate 자동 구성

권장 분리:

- TileSatelliteMotion
- TileSatelliteAppearance
- TileSatelliteVfx
- Editor 전용 제작 도구

확인된 색상 불일치:

- GetEffectiveBuffColor()는 m_buffColor를 그대로 반환한다.
- CreateSatelliteTrailGradient()와 UpdateParticleColor()는 RGB가 모두 0.35 미만이면 보라색으로 바꾼다.
- 따라서 검정 디버프의 본체와 꼬리/파티클 색이 다르게 보인다.

현재 기획대로 같은 색을 쓰려면 어두운 색의 보라색 치환을 제거해야 한다.

EffectManager/EffectPool2D 개선:

- int effectID 대신 enum 또는 EffectKey 사용
- EffectLibrary 목록 외부 수정 차단
- SetDestoryOnFinish 오타 수정
- 반복 파티클이 영원히 반환되지 않는 경우를 막는 최대 수명 추가
- Animator 클립 길이 추정보다 Animation Event 또는 명시 duration 사용


4-15. CameraController와 GlobalClickDetector
--------------------------------------------------------------------------------

CameraController:

- 코루틴 핸들은 static인데 실제 코루틴 owner가 외부에서 전달된다.
- 새 owner가 이전 owner에서 시작된 코루틴을 StopCoroutine으로 멈출 수 없다.
- CameraController 인스턴스가 자신의 코루틴을 직접 소유해야 한다.

GlobalClickDetector:

- 바닥 좌표는 Plane으로 계산하지만 타워 판정은 Physics2D.OverlapPoint와 Collider2D를 사용한다.
- Collider 없는 좌표 기반 보드로 갈 경우 Board.TryGetTower(cell)로 바꿔야 한다.
- PointerEventData와 RaycastResult List는 클릭마다 새로 생성되므로 재사용할 수 있다.


4-16. HPBar, DamageText, Currency
--------------------------------------------------------------------------------

HPBarSlider:

- m_gauge null 검사 뒤 마지막 줄에서 다시 무조건 m_gauge.fillAmount에 접근한다.
- 색상을 계산 전후 두 번 설정한다.
- 함수 시작 시 null이면 반환하고 Clamp한 값을 한 번만 적용한다.

DamageText:

- 데미지를 F2로 고정 표시한다.
- 정수형 데미지 게임이라면 소수 둘째 자리까지 표시할 필요가 없다.

CurrencyManager:

- 재화 상태와 TMP UI를 한 클래스가 관리한다.
- SpendMoney/SpendGem이 성공 여부를 반환하지 않는다.
- 음수 입력을 막지 않는다.
- 보석이 float이어야 하는지 확인이 필요하다.

권장 구조:

- CurrencyWallet: 데이터와 TrySpend
- CurrencyChanged 이벤트
- HudPresenter가 화면 갱신


================================================================================
5. 성능 개선 우선순위
================================================================================

성능은 P0 버그 수정 뒤 진행한다. 현재 보드 규모에서는 작은 할당보다 전역 검색과 반복 타겟 탐색이 우선이다.


5-1. 가장 먼저 제거할 것
--------------------------------------------------------------------------------

1) 투사체 비행 중 매 프레임 FindObjectsByType
2) 모든 타워/디버프 존의 개별 Update 입력 검사
3) 한 공격에서 반복되는 전체 적 타겟 탐색
4) TilePath 조회마다 생성되는 새 List


5-2. 다음으로 줄일 것
--------------------------------------------------------------------------------

1) TowerController.GetFinalStats()의 반복 Dictionary 생성
2) GetSatelliteOffset() 호출마다 생성되는 Vector2 배열
3) sourceID 제거 때 TileManager 전체 셀 순회
4) TilePath의 enemy 위치 탐색 전체 순회
5) UI 타일 목록의 반복 Instantiate/Destroy
6) Projectile VFX 설정의 반복 Gradient/AnimationCurve 생성


5-3. 권장 캐시 단위
--------------------------------------------------------------------------------

- 한 타워 행동: TowerEffectSnapshot + TowerFinalStats
- 한 공격 묶음: 선택된 타겟 또는 TargetSelectionContext
- 한 웨이브: EnemyType Queue
- 한 이펙트 ID: VFX 설정
- 한 적: Movement 컴포넌트와 현재 pathIndex
- 한 effect source: 영향받는 tile cell 목록

9-1. EditMode 테스트

[타워 계산]

- 방어 타일과 해머 디버프가 함께 반영됨
- 풀 부족으로 적 Spawn 실패 시 웨이브가 망가지지 않음
- 느린 투사체가 목표 도달 전에 임의 만료되지 않음
- 버프 타워 위치 순서가 달라도 공격 결과가 같음
- 타워 이동 후 디버프 존 기준 위치가 갱신됨
- 재시작 후 이전 실드/웨이브/코루틴이 남지 않음
- 타일 정보 패널을 연 상태에서 효과 변경이 갱신됨
