수업 중에 정한 것
- 모든 enum의 0번은 None. C#에서 enum의 기본값은 0이라, 값을 정하지 않은 것(모드를 안 고름 등)을 구분해 잡으려고.
  꼭 필요한 곳: AttackAttribute(원소 문양은 속성이 없음), TowerColor(시너지 타워 ID 6014는 백의 자리가 0).
- 적 종류는 기획대로 셋(일반, 중간 보스, 최종 보스). Boss와 FinalBoss가 둘 다 있던 것을 FinalBoss 하나로.
  TargetPriority.Boss는 "최종 보스·중간 보스를 먼저 노림"의 뜻.
- 문양 enum의 이름은 TowerEmblem (계획서의 "Emblem"). 옛 코드에도 같은 이름의 static class(상수 모음, namespace 없음)가 있음.
  namespace SquareTD 안에서는 새 enum이 먼저 찾아지고, 밖(지금의 테스트 파일)에서는 옛 것이 먼저 찾아지므로 SquareTD.TowerEmblem으로 씀.
- 버프·디버프 컬러의 이름을 옐로우·퍼플로 바꿈. 20번 4장 컬러 표·컨셉 표 머리줄·원소 설명, 10장 컬러별 기준의 화이트·블랙을 옐로우·퍼플로 고침
  ("블랙스미스"는 직업 이름이라 그대로).
- GetNextTier는 5티어를 막지 않음 (5107 → 6107 = 시너지 ID가 됨). TowerId는 자리 계산만 하고, 5티어 강화를 막는 것은
  부르는 쪽(수업 19의 TowerProgression)이 함.
- GetColor(시너지 ID) = None은 맞는 결과 (시너지 타워에는 컬러가 없음). GetTier(6014) = 6이므로, 시너지인지 먼저 보고 티어를 씀.

배운 것의 요점
- enum: 숫자에 이름을 붙인 것. 에셋에는 숫자로 저장되므로 중간에 끼우지 않고 맨 뒤에 더함. 숫자는 직접 적음(안 적으면 0부터).
- 형변환: 정수 → enum은 (TowerColor)(식), enum → 정수는 (int)값. 식 전체를 괄호로 감싸야 형변환이 식 전체에 붙음.
- static class: 상태 없이 입력 → 결과만 돌려주는 계산 모음. new 없이 TowerId.GetTier(2107)로 부름.
- 정수 나눗셈: 몫(/)과 나머지(%)로 자리를 잘라 냄. 합칠 때는 자리값을 곱해서 더함.
- bool은 비교식 자체(GetTier(id) == 6)를 그대로 return. 같은 계산은 이미 만든 함수를 다시 불러 한 곳에만 둠.
- switch: case를 이어 쓰면 "이 중 하나면", default는 "그 밖 전부".
- 이름이 옛 코드와 겹치면, 컴파일러는 에러 없이 옛 것을 찾아 버림 (TowerEmblem). 자동 완성에 옛 이름이 뜨면 새 것인지 확인.
- 편집기가 자동으로 넣는 using을 저장 전에 확인. 특히 UnityEditor로 시작하는 using이 게임 스크립트에 들어가면 빌드가 실패함.
- 테스트: [Test]는 바로 아래 함수 하나에만 붙음. Assert.AreEqual(정답, 실제)의 정답은 함수가 돌려주는 형식과 같아야 함
  (정수 5와 TowerEmblem.Shield는 다르다고 판정). 실패하면 Expected / But was 두 줄부터 봄.

만든 파일
- Assets/3. Scripts/New/00. Core/Singleton.cs — public abstract class Singleton<T> : MonoBehaviour where T : MonoBehaviour
    public static T Instance { get; private set; }   누구나 읽고, 바꾸는 것은 이 클래스 안에서만
    protected virtual void Awake()       Instance가 있고 그게 내가 아니면 Destroy(gameObject); return; 아니면 Instance = this as T
    protected virtual void OnDestroy()   Instance가 나였으면 Instance = null
  옛 매니저마다 복사돼 있던 15줄(옛 CurrencyManager.Awake / OnDestroy)과 같은 동작. 새 매니저 9개는 ": Singleton<자기 이름>"으로 물려받음.
확인
- 시험용 TestManager : Singleton<TestManager>를 오브젝트 두 개에 붙여 플레이 → 하나만 남음. 확인 뒤 TestManager.cs를 지움.
- 어느 쪽이 남는지 실험: 하이어라키의 위아래와는 상관없고, 지금 환경에서는 먼저 만든 오브젝트가 먼저 깨어나 남음
  (2를 먼저 만들면 1이 지워짐). Unity가 보장하는 순서가 아니므로 이 순서에 기대는 코드는 쓰지 않기로 함.

배운 것의 요점
- 수명주기: Awake → OnEnable → Start → Update → OnDisable → OnDestroy. Awake는 자기 준비, 다른 매니저를 찾는 것은 Start부터.
- T는 형식의 이름(값이 아님). 검사하고 넣고 비우는 대상은 Instance. this = 나, gameObject = 나를 담은 오브젝트.
- 제네릭 <T>: 형식을 빈칸으로 둔 클래스 (List<int>와 같은 문법). where T : MonoBehaviour = 빈칸에 넣을 수 있는 것의 조건.
- abstract = 물려받아서만 씀. virtual = 자식이 덮어써도 됨. override = 덮어씀. base.Awake() = 부모의 원래 것도 실행
  (자식이 Awake를 덮어쓰며 base.Awake()를 빠뜨리면 Instance가 비어 있음). protected = 자기와 자식만.
- && = 그리고, || = 또는. = 는 값을 넣음, == 는 같은지 비교.
- OnDestroy에서는 아무것도 지우지 않음 (이미 지워지는 중이라 불린 것).

- 스폰 칸은 정렬하지 않고 훑는 순서로 왼쪽 위부터 (계획서의 List.Sort 대신).

배운 것의 요점
- 계산(BoardGrid, 순수 클래스)과 Unity에 기대는 부분(BoardManager, MB)을 나눔 → 계산 쪽은 테스트로 증명.
- 생성자: 이름이 클래스와 같고 돌려주는 형식이 없음. new 할 때 한 번. 매개변수(받는 쪽 빈칸) / 인자(부르는 쪽이 넣는 값).
  매개변수는 그 함수 동안만 있으므로 필드(m_)에 옮겨 적어 둠.
- List(번호 → 값)와 Dictionary(열쇠 → 값). 같은 표를 양쪽으로 빨리 찾으려고 둘 다 둠.
- readonly = 상자를 다른 것으로 바꾸지 못함 (내용 Add는 됨). IReadOnlyList = 그 통로로 내용을 바꾸지 못함.
- => 프로퍼티 = 물어볼 때마다 계산. public int X; 는 빈 상자.
- ( )는 함수 부르기, [ ]는 목록에서 꺼내기. (1, 0, 0)은 튜플이지 Vector3Int가 아님 → new Vector3Int(1, 0, 0).
- Vector3 = 소수(화면 위치), Vector3Int = 정수(칸 번호). 판정·계산은 Vector3Int, 화면에 그릴 때만 Vector3.
- Mathf.Abs·Max는 숫자 하나씩 → a.x, a.y로 꺼내 씀. 아무것도 안 쓰면 private이 기본.
- Try의 out은 실패해도 기본값(0)이 채워짐. 0도 진짜 번호라 bool을 먼저 보고 false면 out 값은 쓰지 않음.
- Assert.IsTrue(조건) / IsFalse(조건)는 bool 하나. 결과가 둘이면 변수로 받아 하나씩 확인.
- cellBounds = 타일이 깔린 곳을 감싸는 사각형(타일맵이 스스로 기록, Max는 마지막 칸의 바로 다음). HasTile로 진짜 칸만 거름.
- base.Awake()의 Destroy는 프레임 끝에 일어나서 자식 Awake는 계속 돎 → if (Instance != this) return;
- MonoBehaviour 파일 이름 = 클래스 이름 (이름은 Unity 프로젝트 창에서 바꿔 .meta가 따라가게).
